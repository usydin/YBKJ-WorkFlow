# 样本管理说明

## 目的

本项目的样本管理用于支持本地离线解析规则优化、人工确认对照和后续训练资料沉淀。

样本的核心目标是帮助系统逐步从“可录入”演进到“可解析、可确认、可复用”，而不是围绕截图本身建立单一流程。

## 当前样本目录

- `dataset/samples/screenshots_raw`
- `dataset/samples/text_samples`
- `dataset/samples/parsed_expected`

## 当前规则

### 1. 原始长图样本

- `screenshots_raw` 中的微信长图仅作为当前阶段本地视觉参考样本
- 不建议将高清长图提交到 GitHub
- 当前已通过 `.gitignore` 忽略该目录中的图片文件
- 目录本身保留 `.gitkeep`，便于工程结构稳定存在

### 2. 文本样本

- 后续主输入路径优先是：
  - 复制微信文本并粘贴
  - 单个 TXT 导入
  - 批量 TXT 导入
  - 手动补录
- `text_samples` 可以保留少量脱敏文本样本，便于提交到仓库

### 3. 解析期望样本

- `parsed_expected` 用于存放“原始文本 -> 期望解析结果”的对照样本
- 该目录适合后续保留少量示例文本或 JSON 结果，便于回归验证

## OCR 定位

- OCR 只是后续可选输入插件能力
- OCR 不是 `V1.0 beta` 主路径
- 本轮不实现 OCR

## 后续训练与优化来源

后续解析优化主要依赖以下资料：

- 文本样本
- `parsed_records` 的人工确认结果
- `dataset/corrections.log`

## 建议

- 图片样本尽量只保留本地调试所需数量
- 提交到仓库的文本样本应尽量脱敏
- 后续优先构建“文本样本 + 人工确认结果”的持续优化闭环
