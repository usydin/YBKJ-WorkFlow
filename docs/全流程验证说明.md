# 全流程验证说明

## 目标

本文用于验证 `V0.3-real-sample-run` 阶段是否形成可演示、可检查、可导出的真实业务闭环。

本轮验证重点：

- 数据录入可用
- 智能解析可用
- 人工确认可用
- 员工映射可用
- 日报生成可用
- Excel 导出可用
- 统计分析可用
- 数据质量检查可用

## 启动程序

1. 安装依赖：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

2. 启动程序：

```bash
.venv/bin/python app.py
```

3. 编译检查：

```bash
.venv/bin/python -m compileall app engine tests
```

## 导入演示文本

建议优先使用以下样例文件：

- `dataset/samples/text_samples/realistic_wechat_records_sample.txt`
- `dataset/samples/text_samples/demo_daily_records.txt`

其中 `realistic_wechat_records_sample.txt` 已覆盖以下情况：

- 正常消防维修记录
- 正常视频监控维修记录
- 微信网名 `王权富贵`
- 微信网名 `王权富贵Dr.`
- 维修人员缺失
- 地点缺失
- 系统类别不明确
- 工作类型待人工确认
- 只有简短描述
- 多人参与但人员不清晰
- 疑似重复记录
- 保留名 `ybkj-pL` 误入防护验证

导入方式：

1. 打开“数据录入”页。
2. 选择默认项目，或直接粘贴演示文本。
3. 可使用 TXT 导入，也可直接粘贴样例内容。
4. 推荐优先使用 `realistic_wechat_records_sample.txt` 做本轮真实样例闭环试跑。
4. 点击提交，确认提示成功。

## 执行智能解析

1. 进入“智能解析”页。
2. 点击“解析待处理文本”。
3. 确认：
   - 待解析数量减少；
   - `parsed_records` 列表出现新的解析结果；
   - `王权富贵`、`王权富贵Dr.` 映射后可回填真实姓名；
   - 缺少人员、地点、系统类别、工作类型不明确的记录仍会进入待确认流程；
   - 简短描述和多人参与不清晰的记录不会被直接丢弃。

## 进入人工确认

1. 打开“人工确认”页。
2. 逐条检查 `confirm_status = pending` 的记录。
3. 重点验证：
   - 缺少日期、项目、系统类别、工作类型、维修人员的记录可编辑；
   - 缺少地点的记录可补全；
   - “重新映射人员”按钮可用；
   - 详情区“修正提示”能提示当前记录需要补哪些关键字段；
   - 保存、确认、忽略、恢复按钮均不报错；
   - `ybkj-pL` 不会进入 `worker_names` 字段。

## 重新映射人员

1. 打开“员工映射”页。
2. 确认以下映射仍然成立：
   - `王权富贵 -> 王立彦`
   - `王权富贵Dr. -> 王立彦`
3. 如果演示数据中存在未解析网名，可新增或调整别名映射。
4. 返回“人工确认”页重新执行“重新映射人员”。

## 生成日报

1. 将部分记录确认成 `confirmed`。
2. 进入“日报生成”页。
3. 设置日期或筛选条件，点击“生成日报”。
4. 确认：
   - 页面能显示日报文本；
   - 可复制到剪贴板；
   - 可导出到 `reports/daily/`。

## 导出 Excel

1. 打开“Excel导出”页。
2. 选择与日报一致的筛选条件。
3. 点击导出。
4. 确认：
   - 成功生成 Excel；
   - 文件位于 `outputs/excel/`；
   - 仅包含 `confirmed` 记录。

## 查看统计分析

1. 打开“统计分析”页。
2. 点击“刷新统计”。
3. 确认：
   - 总览卡片正常显示；
   - 按人员、项目、系统类别、工作类型、明细记录均可查看；
   - 员工映射变化会反映到统计结果中。

## 运行数据质量检查

1. 打开“数据质量”页。
2. 点击“开始检查”或“刷新”。
3. 确认：
   - 能显示原始输入、解析记录、员工映射、导出准备等指标卡片；
   - 能显示问题清单表格；
   - 页面包含“规则说明”小节；
   - “综合结论”能展示 `正常 / 需要关注 / 需要处理`；
   - 点击“导出检查结果”后能生成 Markdown 报告到 `reports/quality/`；
   - 报告中能看到缺少地点、疑似重复和保留名规则相关提示；
   - 检查过程只读，不会自动修改数据库内容。

## 本轮通过标准

满足以下条件即可认为 `V0.3-real-sample-run` 通过：

1. 程序可以正常启动。
2. 数据录入、智能解析、人工确认、员工映射、日报生成、Excel 导出、统计分析、数据质量页面都能打开。
3. 演示样例能够完成“录入 -> 解析 -> 人工确认 -> 导出 -> 质量检查”的闭环。
4. `王权富贵` 与 `王权富贵Dr.` 可以正确映射到 `王立彦`。
5. `ybkj-pL` 不会进入维修人员字段。
6. 缺字段记录、疑似重复记录和保留名问题能在数据质量页暴露。
7. 数据质量页可以成功导出 Markdown 检查报告。
8. 统计分析页能看到试跑后的记录数量和人员/类型统计。
9. 检查与导出不会自动改写业务数据。

## 建议验证顺序

```text
数据录入 -> 智能解析 -> 人工确认 -> 员工映射 -> 日报生成 -> Excel导出 -> 统计分析 -> 数据质量检查
```
