# V0.3 真实样例闭环试跑说明

## 1. 阶段目标

`V0.3-real-sample-run` 的目标不是扩展 OCR、Word/PDF 或大模型能力，而是让用户使用几条真实/半真实、已脱敏的微信维修记录，在当前 GUI 内完成一次完整闭环试跑：

`数据录入 -> 智能解析 -> 人工确认 -> 员工映射检查 -> 数据质量检查 -> 日报生成 -> Excel 导出 -> 统计分析`

重点是让问题能够被看见、被修正、被复验。

## 2. 使用样例数据的位置

推荐样例文件：

- `dataset/samples/text_samples/realistic_wechat_records_sample.txt`
- `dataset/samples/text_samples/demo_daily_records.txt`

其中 `realistic_wechat_records_sample.txt` 更接近真实微信群口吻，覆盖：

- 正常消防维修记录
- 正常视频监控维修记录
- `王权富贵`
- `王权富贵Dr.`
- 缺少维修人员
- 缺少地点
- 缺少系统类别
- 同一工作重复上报
- 只有简短描述
- 多人参与但人员不清晰
- 需要人工确认工作类型
- 保留名 `ybkj-pL` 误入防护验证

## 3. 启动程序命令

```bash
.venv/bin/python app.py
```

如需先做编译检查：

```bash
.venv/bin/python -m compileall app engine tests
```

## 4. 录入样例文本步骤

1. 打开“数据录入”页。
2. 选择默认项目，可保持默认值。
3. 使用以下任一方式导入样例：
   - 直接复制 `realistic_wechat_records_sample.txt` 内容后粘贴到文本区。
   - 点击“导入 TXT”，选择 `dataset/samples/text_samples/realistic_wechat_records_sample.txt`。
4. 确认页面提示提交成功，数据进入 `raw_inputs` 待解析队列。

## 5. 智能解析步骤

1. 进入“智能解析”页。
2. 点击“解析待处理文本”。
3. 确认解析完成后：
   - `raw_inputs` 中待解析数量下降；
   - 新记录进入 `parsed_records`；
   - 样例中的微信口吻文本被拆分为可确认记录；
   - 不能稳定识别的字段进入待确认状态，而不是被静默丢弃。

## 6. 人工确认步骤

1. 进入“人工确认”页，筛选 `confirm_status = pending`。
2. 逐条查看记录详情区上方的“修正提示”。
3. 优先处理以下问题：
   - 缺少维修人员
   - 缺少地点
   - 缺少系统类别
   - 缺少工作类型
   - 人员待确认
   - 保留名误入维修人员
4. 必要时修改日期、项目、地点、设备/部位、问题描述、处理方法和备注。
5. 修正完成后点击“保存修改”或“确认为有效记录”。

## 7. 员工映射检查步骤

1. 打开“员工映射”页。
2. 确认以下映射存在且启用：
   - `王权富贵 -> 王立彦`
   - `王权富贵Dr. -> 王立彦`
3. 如解析结果中出现未识别网名，可补充或调整别名映射。
4. 返回“人工确认”页，点击“重新映射人员”验证映射结果是否回填。

## 8. 数据质量检查步骤

1. 打开“数据质量”页。
2. 点击“开始检查”或“刷新”。
3. 重点观察以下问题是否被暴露：
   - 未解析
   - 待确认
   - 人员未确认
   - 系统类别缺失
   - 工作类型缺失
   - 疑似重复
   - `ybkj-pL` 保留名误入
4. 点击“导出检查结果”，确认生成 Markdown 报告。
5. 检查报告中同时应包含“规则说明”小节。

## 9. 日报生成步骤

1. 确认至少有一部分记录已设置为 `confirmed`。
2. 打开“日报生成”页。
3. 设置日期或筛选条件后点击“生成日报”。
4. 检查：
   - 页面有可读日报文本；
   - 已确认记录能进入日报；
   - 待确认或已忽略记录不会误入日报；
   - 支持导出 TXT / Markdown。

## 10. Excel 导出步骤

1. 打开“Excel导出”页。
2. 使用与日报相同或相近的筛选条件。
3. 点击导出。
4. 确认导出的 Excel 文件生成成功，且仅包含 `confirmed` 记录。

## 11. 统计分析检查步骤

1. 打开“统计分析”页。
2. 点击“刷新统计”。
3. 检查：
   - 已确认记录数正常显示；
   - 人员统计中能看到 `王立彦`；
   - 按系统类别和按工作类型统计可查看；
   - 明细记录能显示样例试跑后的结果。

## 12. 验收标准

满足以下条件可认为本轮试跑通过：

- 样例文本可录入
- 智能解析能生成 `parsed_records`
- `王权富贵` / `王权富贵Dr.` 能映射到 `王立彦`
- `ybkj-pL` 不进入维修人员字段
- 缺字段记录能在数据质量检查中暴露
- 已确认记录能生成日报
- 已确认记录能导出 Excel
- 统计分析页能显示记录数量和人员/类型统计
- 数据质量检查报告可导出 Markdown

## 13. 常见问题

### Q1. 没有看到导入按钮怎么办？

当前版本的数据录入页已经支持 `.txt` 导入；如果现场不方便操作文件选择，也可以直接复制样例文本后粘贴。

### Q2. 解析后维修人员为空怎么办？

先看“人工确认”页的修正提示，再检查“员工映射”页是否已维护网名与真实姓名关系；必要时手工补全并保存。

### Q3. 为什么有些记录没有直接进入日报？

日报和 Excel 仅使用 `parsed_records.confirm_status = confirmed` 的记录。待确认记录需要先人工核对。

### Q4. 数据质量页提示疑似重复，是不是系统会自动删除？

不会。当前只做提示，不自动删除，由人工决定保留、修正或忽略。

### Q5. 为什么 `ybkj-pL` 还会出现在原文里？

原文会完整保留在 `raw_inputs` 和 `source_raw_text` 中；规则限制的是它不能作为维修人员写入 `worker_names`。

## 14. 下一步进入 OCR 前需要确认的事项

在进入 OCR 前，建议先确认以下事项已经稳定：

1. 文本录入、TXT 导入和手工补录已经够用。
2. 真实样例的主要解析问题都能在人工确认页被快速修正。
3. 员工映射规则和保留名规则已经稳定，不会污染统计结果。
4. 数据质量检查项能稳定暴露关键问题，并支持 Markdown 导出留档。
5. 日报、Excel 和统计分析都基于 `confirmed` 记录稳定工作。
6. 当前数据库结构无需为 OCR 进行破坏性调整。

## V0.4 更新提示

在 `V0.4-real-input-polish` 中新增了以下与试跑相关的轻量优化，不改变本说明主体流程：

- 数据录入页增加“真实文本试跑提示”卡片与“载入真实样例”按钮，并显示输入统计。
- 智能解析将规则型“解析提示”写入 `parsed_records.note`；解析页新增“解析提示”列。
- 人工确认页基础信息顶部新增“解析提示 / 待补全项”提示条，随编辑即时刷新。
- 数据质量报告与页面增加“待处理指引”小节。
- 日报与 Excel 页面增加范围提示与待确认数量展示，明确仅导出 `confirmed` 记录。
