# 人工确认流程说明

## 数据分层

系统当前按以下三层划分数据：

1. `raw_inputs`
   - 原始输入池
   - 保留完整原文
   - 不允许被解析结果覆盖

2. `parsed_records`
   - 解析后的结构化记录
   - 当前作为待人工确认数据池

3. `confirmed` 记录
   - `parsed_records.confirm_status = confirmed`
   - 是后续日报、统计、Excel 导出的可信来源

## confirm_status 定义

- `pending`：待确认
- `confirmed`：已确认
- `ignored`：已忽略

说明：

- `ignored` 记录默认不参与后续导出
- `pending` 记录仍属于待人工核定状态

## 页面操作

人工确认页当前支持以下动作：

### 1. 保存修改

- 更新当前记录的可编辑字段
- `confirm_status` 保持不变
- 追加写入 `dataset/corrections.log`

### 2. 确认为有效记录

- 保存当前编辑结果
- 将 `confirm_status` 设为 `confirmed`
- 如果 `worker_names` 已填写，则 `employee_confirm_required` 自动置为 `false`
- 追加写入 `dataset/corrections.log`

### 3. 忽略该记录

- 将 `confirm_status` 设为 `ignored`
- 追加写入 `dataset/corrections.log`

### 4. 恢复为待确认

- 将 `confirm_status` 设为 `pending`
- 追加写入 `dataset/corrections.log`

## corrections.log 作用

`dataset/corrections.log` 当前采用 JSONL 形式，每行记录一次人工修正行为。

当前记录字段包括：

- `correction_time`
- `operator_name`
- `action_type`
- `record_id`
- `raw_input_id`
- `before`
- `after`
- `source_raw_text`
- `note`

## 当前边界

- 本轮不实现 OCR
- 本轮不实现 Excel 导出
- 本轮不实现复杂模型训练
- 本轮不实现 employee_aliases 的完整管理页面
