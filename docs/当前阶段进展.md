# 当前阶段进展

## 阶段定位

当前阶段为 `V1.0 beta` 的数据录入与持久化闭环开发阶段。

本轮目标是打通非结构化数据进入系统的第一道关口，实现从“用户录入”到“本地数据库+离线备份”的完整留痕。

## 本次完成内容

### 1. 数据录入能力

- **多源录入**：
  - 微信文本粘贴：大块文本直接粘贴。
  - TXT 导入：支持 `.txt` 文件批量载入文本区。
  - 手动录入：支持输入框手动追加内容。
- **录入元数据**：支持选择操作员姓名（ybkj-pL 等）和默认项目（石炼化、康石、人才公寓等）。
- **交互闭环**：提交前校验非空，提交后自动清空并弹出成功提示，同步刷新首页统计。

### 2. SQLite 业务存储

- **RawInputs 表**：
  - 字段：`id`, `created_at`, `operator_name`, `source_type`, `default_project`, `raw_text`, `status`, `note`。
  - 自动初始化：程序启动时自动检查并补齐业务表结构。

### 3. JSONL 原始输入备份

- **同步追加**：每次成功提交数据库的同时，将完整 JSON 记录追加到 `datapool/jsonl/raw_inputs.jsonl`。
- **数据容灾**：即使数据库损坏，也能通过 JSONL 还原所有原始输入。

### 4. 工作台仪表盘接入

- **实时查询**：首页“今日记录数”和“待人工确认数量”卡片已接入数据库查询，实时反馈系统载入情况。

### 5. 架构优化

- **IntakeService**：引入服务层协调 UI 与存储层，解耦业务逻辑。
- **统一常量管理**：在 `app/config.py` 统一管理项目选项与记录状态。

## 当前可运行状态

当前版本已经具备以下运行能力：

- 可通过数据录入页提交维保信息。
- 提交后本地 `ybkj_workflow.db` 和 `raw_inputs.jsonl` 同步更新。
- 首页统计卡片实时反映入库条数。
- 完整的运行日志留痕（包含录入操作记录）。

## 下一阶段建议

1. **智能解析引擎**：接入正则、关键词与 RapidFuzz 逻辑，将 `raw_text` 转化为结构化字段。
2. **待确认池**：实现“智能解析”页面，支持人工核对解析后的字段（项目、系统、工时等）。
3. **数据池视图**：实现“数据池”页面，支持查看、筛选与编辑已确认的记录。
4. **Excel 导出**：实现基于 `openpyxl` 的基础导出功能。
