# 员工映射规则

## 背景

微信长图或聊天记录中显示的往往是微信网名，而不是标准员工姓名。

系统最终生成的日报和 Excel 台账需要使用真实员工姓名。因此，系统维护了一个“微信网名/别名 -> 真实姓名”的映射表。

## 映射逻辑

### 1. 解析阶段自动映射
- `ParserEngine` 在解析出 `wechat_nickname`（微信网名）后，会调用 `resolve_worker_names` 逻辑。
- 系统会尝试将网名拆分为多人（支持 `、`, `，`, `,`, ` `, `/`, `；`, `;` 等分隔符）。
- 对拆分出的每个名字，在 `employee_aliases` 表中查找匹配项（匹配 `real_name`, `wechat_nickname`, 或 `alias`）。
- **映射成功**：将 `real_name` 填入 `worker_names` 字段。
- **部分/全失败**：保留原网名，并标记 `employee_confirm_required = true`。

### 2. 人工确认页手动映射
- 如果自动映射未覆盖或映射有误，操作员可以在人工确认页点击 **“根据网名映射人员”** 按钮。
- 系统会再次尝试基于当前填写的网名进行实时匹配并补全真实姓名。

## 软删除与管理
- 映射记录支持 `is_active` 状态。
- 解析引擎仅使用 `is_active = 1`（启用）的记录进行自动映射。
- 停用的记录仍保留在数据库中以备追溯，但不会参与自动匹配。

## 多人处理规则
- 输入：`张三(网名)、李四(昵称)`
- 映射表：`张三(网名) -> 张小三`, `李四(昵称) -> 李小四`
- 输出：`张小三、李小四`
- 规则：映射后会自动去重并保持原始顺序。

## 设计原则
1. **真实性优先**：日报和 Excel 必须尽量使用真实姓名。
2. **原始追溯**：始终保留 `wechat_nickname` 原始字段，不丢失来源信息。
3. **人工兜底**：自动映射仅作为辅助，最终结果由人工在“人工确认”页定稿。
4. **留痕参考**：人工修正的结果记录在 `corrections.log` 中，可作为后续优化映射表的参考。
